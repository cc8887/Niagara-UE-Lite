# UE 5.9 Preview package

The separate UE 5.9.0 Windows release targets CL 60351404, Release-5.9.
Keep the UE 5.8.1 releases available separately. Match the asset producer,
native backend, Shipping binary, shaders and cache to the chosen build.
The frontend reads its engine version from the bundled Build.version.
The final release notes and attached reports are the qualification authority;
successful compilation alone is not rendering or package acceptance.

## Native build

Use an independent source/build tree with the matching UE SDK and precompiled
libraries. Preserve the installed engine, existing project workspaces and prior
release artifacts. The editor backend profile rebuilds UnrealEd, LevelEditor,
MeshUtilities and Blutility. The generic-authoring and stack-identity patches
also require rebuilding NiagaraEditor, then the project worker.

The generic export and commandlet-profile patch helpers accept UE 5.8.1 and
5.9.0. Stack identity distinguishes 5.9's explicit SimulationStage pointer from
the older resolver: qualified usage GUIDs remain supported for both Event and
Simulation Stage stacks, and conflicting identities are rejected.

UE 5.9 moved the real fx.GPUSimulationTextureSizeX/Y variables to
CascadeVertexFactories while RendererSettings still imports them. Apply
`patch_ue59_backend_compat.py --engine <isolated-Engine> --project <project> --apply`
before Cook. This keeps the actual CascadeVertexFactories/CascadeRuntime service
modules in the authoring backend, with an Editor-only project reference. It
disables the Cascade editor toolkit and its Takes dependency in this dedicated
backend profile. No dummy variables, ignored Cook errors or fake module symbols
are used. The public CLI still does not author Cascade effects or materials.

The same profile enables the real SequencerScripting service with an Editor-only
project reference, excluding SequencerScriptingEditor. MovieSceneTimeWarpVariant
declares HasNativeMake/HasNativeBreak functions in that module; Python wrapper
generation otherwise reports missing functions and fails commandlet execution,
even if a texture was saved. Keep the actual functions instead of ignoring the
process failure or deleting reflection metadata.

An installed engine can contain unrelated custom target/platform source whose
third-party build inputs are absent. Do not rebuild those targets or substitute
placeholder implementations. Reuse the matching installed precompiled modules
where supported; isolate unrelated incomplete application rules in the task's
build copy. The Windows package targets D3D12/SM6, not those optional platforms.

## Package and validate

Set `NIAGARA_PACKAGE_ENGINE_VERSION=5.9.0` before importing/running the packaging
tools. The default stays 5.8.1 for existing build workflows. The 5.9 stage adds
the adapted Cascade descriptor and its actual native backend modules.

Retain only the UnrealEditor, ShaderCompileWorker and UnrealPak program families;
exclude CEF, external/static symbols, developer SDK files and optional Vulkan
tools/layers. Evaluate material/texture UI candidates against the actual binary
imports. Determine the active ICU data root from the actual Core binaries.
Resource pruning requires a fresh matching native reference inventory; an old
5.8 inventory cannot establish a 5.9 resource closure.

Seal a frozen file list with per-file hashes and the source commit. From the
extracted archive, clear developer engine/project/runtime overrides and verify
template-free System/Emitter creation, editing, save/reload, texture import,
existing material bindings, JSON round-trip, Cook and native GPU Sprite,
Ribbon and Mesh PNGs. Include native Event/Simulation Stage identity checks.
Report the full compressed archive size separately from optional DDC and
logical payload. Linux requires its own matching 5.9 build and qualification;
the Windows install and the previous Linux 5.8 package are not substitutes.

JSON native extensions require the same engine build. An older uncooked asset
may be upgraded by UE's native loader, but no universal backward save or JSON
cross-version compatibility is promised. Do not install a 5.8 DDC into a new
5.9 workspace.
